# Actual UI failures found and corrected

These notes preserve observed AI implementation problems. They do not supply the student's personal evaluation, claim an outside tester, or invent challenge outcomes. Date: November 8, 2026, Asia/Manila.

| Finding | Original implementation / actual failure | Correction | Evidence / verification |
| --- | --- | --- | --- |
| Font incorrectly treated as variable | Google CSS request returned a static `DMSans-Black` TTF, but AI saved it under a WOFF2 name and declared 100–900. Browser computed 400 while every glyph was visually heavy; native CoreText reported no variation axes. | Use the actual DM Sans variable TTF from Google Fonts source, proper extension and local loading. Native inspection confirms optical-size 9–40 and weight 100–1000; app registers 100–900. | `issues/font-before.png`, `font-source-before.txt`; corrected code/asset in public/fonts; `tests/font.test.ts` reads the actual fvar table and passes. |
| Populated cart hydration mismatch | Provider subscribed to storage and passed already-hydrated item arrays through context to a later-hydrating Header Suspense boundary. Actual refresh regression reported server count 0 versus client 2 and React hydration failure. | Context holds a stable store/actions; each useCart consumer subscribes with its own stable server snapshot. | `issues/cart-context-before.txt`, `hydration-failure.txt`; corrected source `src/components/cart-context.tsx`; populated refresh in customer/motion browser tests. |
| Native dialog Tab cycle left content | The initial implementation relied only on native modal semantics. Actual Chrome trace moved through five cart controls and then set activeElement to BODY on Tab 6. | Cycle the complete visible DOM focus order for Tab/Shift+Tab, retaining native dialog/inert semantics and Escape logic. Record the explicit opener and restore it after native close: Safari clicking a button need not focus it. A boundary-only first attempt passed Chrome but was insufficient in WebKit; that intermediate version is also preserved. | `issues/modal-shell-before.txt`, `focus-failure.txt`; corrected ModalShell; focused browser containment and opener-return tests. |
| Root-only modal scroll lock leaked in WebKit | With only documentElement overflow hidden, the actual WebKit 390px reduced-motion run moved the background from scrollY 747 to 1247 after a 500px wheel input. | Lock both root and body overflow while open, restore both original inline styles on close/unmount, and retain independently scrolling drawer content. | `issues/scroll-lock-failure.txt`; original root-only shell in `issues/modal-shell-before-webkit.txt`; corrected ModalShell; all nine final browser cases check wheel blocking. |
